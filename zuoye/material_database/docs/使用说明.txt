# 动态材料数据库系统使用说明

## 一、系统概述

动态材料数据库系统是一套基于 Flask 框架构建的现代化数据管理平台，专为材料科学领域的数据存储、查询和分析而设计。该系统采用灵活的动态表结构，能够适应不同类型材料数据的存储需求，同时提供了完善的权限管理体系，确保数据安全与访问控制。

本系统的核心优势在于其动态数据模型设计。与传统固定结构的数据库不同，动态材料数据库允许用户根据实际需求灵活定义数据表的字段结构，无需修改数据库 schema 即可适应多变的业务场景。无论是金属材料、聚合物、复合材料还是其他材料类型的数据，都可以在同一平台上进行统一管理和分析。

系统提供了直观的 Web 界面和完整的 RESTful API 接口，既适合非技术用户通过浏览器进行日常操作，也支持开发者通过 API 集成到现有工作流程中。数据导入功能支持标准的 Excel 格式，用户只需上传文件即可完成批量数据导入，极大简化了数据录入工作。权限管理模块实现了细粒度的访问控制，管理员可以为不同用户分配差异化的数据访问权限，确保敏感数据得到妥善保护。

## 二、环境配置

### 2.1 系统要求

在部署本系统之前，请确保目标服务器满足以下基本要求。操作系统方面，系统支持 Windows、Linux 和 macOS 三大主流平台，建议使用 Windows 10 及以上版本或 Ubuntu 20.04 及以上版本以获得最佳兼容性。Python 版本要求 3.8 或更高版本，推荐使用 Python 3.10 或 3.11 以获得最佳性能和稳定性。内存方面，建议至少配置 4GB 可用内存，对于处理大规模数据导入或并发访问的场景，建议配置 8GB 或更多内存。存储空间方面，根据预估的数据量，建议预留足够的磁盘空间用于存储数据库文件、上传的 Excel 文件以及系统日志。

### 2.2 安装步骤

系统采用 Python 的虚拟环境进行依赖管理，确保与系统其他 Python 项目相互隔离。首先，打开终端或命令提示符，进入项目根目录 `material_database`。执行以下命令创建虚拟环境并激活：

```bash
python -m venv venv
```

在 Windows 系统上，激活虚拟环境的命令为 `venv\Scripts\activate`，在 Linux 或 macOS 系统上则为 `source venv/bin/activate`。激活虚拟环境后，终端提示符前会显示 `(venv)` 标识，表示虚拟环境已成功激活。

接下来安装项目依赖包。系统所需的依赖项已在 `requirements.txt` 文件中明确定义，执行以下命令即可完成安装：

```bash
pip install -r requirements.txt
```

安装过程可能需要几分钟时间，取决于网络连接速度和系统性能。如果遇到网络超时问题，可以尝试使用国内镜像源或手动逐个安装依赖包。安装完成后，可以通过以下命令验证关键依赖包是否正确安装：

```bash
pip show flask flask-sqlalchemy flask-login openpyxl
```

如果所有包都显示正常版本信息，则说明安装成功。

### 2.3 数据库初始化

系统使用 SQLite 作为默认数据库，数据库文件存储在 `material_database/data/app.db` 路径下。在首次运行系统之前，需要执行数据库初始化脚本以创建所需的表结构和初始数据。执行初始化命令：

```bash
python init_db.py
```

初始化脚本将自动创建所有数据库表、生成必要的索引，并创建一个默认的管理员账户。初始化完成后，控制台会显示初始化成功的提示信息。

如果需要重新初始化数据库（将清除所有现有数据），可以添加 `--force` 参数：

```bash
python init_db.py --force
```

### 2.4 配置说明

系统的主配置文件位于 `material_database/config.py`，其中包含了数据库连接、文件上传、密钥配置等重要参数。在部署到生产环境时，强烈建议修改以下配置项：

首先是 `SECRET_KEY`，这是 Flask 用于签名会话 Cookie 的密钥，生产环境应使用随机生成的复杂字符串，可以通过 Python 的 secrets 模块生成。其次是 `ADMIN_USERNAME` 和 `ADMIN_PASSWORD`，默认的管理员账户凭据应在首次登录后立即修改。此外，如果需要使用其他数据库服务器（如 MySQL 或 PostgreSQL），可以修改 `SQLALCHEMY_DATABASE_URI` 配置项。

## 三、快速开始

### 3.1 启动服务

完成环境配置后，即可启动系统服务。在项目根目录下执行以下命令：

```bash
python run.py
```

默认情况下，服务将在 `http://127.0.0.1:5000` 上启动。如果需要修改端口号，可以在启动命令中指定：

```bash
python run.py --port 8080
```

服务启动后，打开浏览器访问 `http://127.0.0.1:5000`（或自定义端口）即可看到系统登录页面。在开发模式下，服务启动后会监听代码文件的更改并自动重新加载，这对于开发调试非常方便。

### 3.2 登录系统

首次使用系统时，需要使用初始化过程中创建的默认管理员账户登录。默认管理员用户名为 `admin`，密码为 `admin123`。登录后，系统会立即要求修改默认密码以确保账户安全。

登录流程设计为防止暴力破解攻击，连续多次登录失败将触发账户锁定机制。首次登录后，建议立即进入用户设置页面，绑定邮箱或设置安全问题以增强账户恢复能力。同时，为了保障系统安全，请确保密码符合复杂度要求：至少包含 8 个字符，同时包含大写字母、小写字母、数字和特殊字符。

### 3.3 界面导航

登录成功后，系统将显示主控制台界面。顶部导航栏提供了主要功能模块的快捷入口，包括数据源管理、数据表查看、用户管理、系统管理等。左侧边栏根据当前用户权限动态显示可访问的功能菜单，右侧主区域则展示具体功能的内容和操作界面。

仪表板页面提供了系统概览信息，包括数据源总数、数据表数量、用户数量、近期活动记录等统计图表。通过仪表板，管理员可以快速了解系统运行状态和数据增长趋势。新用户首次登录时，仪表板还会显示欢迎信息和快速上手指南。

## 四、用户管理

### 4.1 用户注册

系统支持用户自主注册功能。在登录页面点击「立即注册」链接，即可进入用户注册页面。注册时需要填写以下信息：用户名、邮箱地址、密码和密码确认。用户名用于系统登录和身份标识，应使用英文字母、数字和下划线的组合，长度在 3 到 20 个字符之间。邮箱地址将用于接收系统通知和密码找回邮件，请确保填写有效的邮箱地址。

密码设置需要满足复杂度要求，系统会实时显示密码强度指示器。当密码强度达到「强」级别时，才可以提交注册表单。注册提交后，系统将向填写的邮箱地址发送验证邮件，用户需要点击邮件中的验证链接完成邮箱验证。邮箱验证是确保账户安全和便于找回密码的重要步骤，虽然在某些配置下可以跳过验证，但强烈建议完成验证流程。

### 4.2 登录与认证

用户登录时需要提供用户名（或邮箱）和密码。系统支持「记住我」功能，勾选后将在浏览器中保存登录状态 7 天，期间无需重复登录。对于组织内部使用场景，建议在受信任的设备上使用此功能，公共场所的计算机则应避免勾选。

会话管理功能允许用户查看和管理当前的登录设备。在用户设置页面，可以查看所有活跃会话的详细信息，包括登录时间、IP地址、设备类型等。如果发现异常登录活动，可以立即终止该会话并修改密码以保护账户安全。系统还支持单点登录（SSO）配置，企业用户可以将系统集成到现有的身份认证体系中。

### 4.3 用户权限类型

系统定义了三种用户角色，每种角色拥有不同的系统权限。普通用户是基础角色，可以浏览被授予权限的数据源、查看数据表内容、执行查询操作，以及导入 Excel 数据到有权限的数据源中。管理员用户除了拥有普通用户的全部权限外，还可以管理用户账户、分配和回收数据源权限、查看系统日志和审计信息。超级管理员是系统的最高权限角色，可以执行所有管理操作，包括系统配置修改、角色权限调整、数据源删除等敏感操作。

在用户管理页面，管理员可以查看所有用户列表，了解每个用户的注册时间、最后登录时间、当前状态等信息。系统提供了便捷的用户搜索和筛选功能，可以按用户名、邮箱、角色类型、注册时间等条件进行筛选。对于离职或长期不活跃的用户账户，管理员可以选择禁用账户而非删除，以便保留历史数据。

## 五、数据源管理

### 5.1 创建数据源

数据源是组织和管理材料数据的核心概念，每个数据源代表一个独立的数据集，通常对应一个 Excel 文件或一类相关的材料数据。创建数据源的步骤如下：首先在左侧导航栏点击「数据源管理」，进入数据源列表页面；然后点击页面右上角的「新建数据源」按钮；在弹出的表单中填写数据源名称、描述信息，并选择数据来源方式。

数据来源支持两种模式：上传新文件和关联现有文件。如果选择上传新文件，系统将显示文件上传区域，支持拖拽或点击选择 Excel 文件（.xlsx 或 .xls 格式）。上传完成后，系统会自动解析文件结构并创建相应的数据表。如果选择关联现有文件，则可以从已上传的文件中选择一个进行关联，适合从历史文件中导入数据的场景。

数据源描述信息应填写能准确反映数据内容的说明，便于其他用户理解数据用途和范围。对于包含敏感信息的数据源，建议在描述中注明访问限制说明。创建数据源时，还可以设置是否允许其他用户请求访问权限、是否在数据源列表中公开显示等选项。

### 5.2 上传和导入数据

数据导入功能支持将 Excel 文件中的数据批量导入到系统中。支持的 Excel 格式包括 .xlsx（Excel 2007 及以后版本）和 .xls（Excel 97-2003 格式）。单个文件大小限制为 50MB，超出限制的文件需要分割后分批上传。

导入流程设计为简单直观：选择要导入的数据源，进入数据源详情页，点击「导入数据」按钮，选择本地 Excel 文件，确认导入设置后开始导入。系统会自动检测 Excel 文件的结构，包括列名、数据类型等，并提供预览功能供用户确认。如果文件中的列名与现有数据表结构不匹配，系统会提示用户进行映射配置。

数据导入过程中，系统会实时显示导入进度和状态。对于大型文件，导入操作可能在后台异步执行，用户可以关闭页面稍后查看结果。导入完成后，系统会生成详细的导入报告，包括成功导入的记录数、跳过的记录数、遇到的错误等信息。如果部分数据导入失败，可以根据错误报告修改源文件后重新导入失败的部分。

### 5.3 数据源权限分配

数据源创建者默认拥有该数据源的所有权限，包括查看、查询、导入、编辑和删除权限。其他用户若要访问数据源，需要获得相应的权限授予。权限分配通过数据源详情页的「权限管理」选项卡进行管理。

添加权限时，需要选择目标用户、权限类型和有效期。权限类型包括：查看表头权限允许用户查看数据表的字段结构和元数据；查询权限允许用户检索和浏览数据表中的记录；导入权限允许用户向数据源中导入新的 Excel 数据；编辑权限允许用户修改字段定义和数据源属性；管理权限包含以上所有权限并可进行授权操作。

权限可以设置为临时有效，在授予时指定过期日期，到期后系统自动回收该权限。这一功能适用于临时协作场景或外部分享场景。系统还支持批量权限管理，可以同时为多个用户授予或回收权限，提高管理效率。所有权限变更都会记录在审计日志中，管理员可以追溯权限分配的完整历史。

### 5.4 数据源操作

在数据源列表页面，每个数据源都提供了丰富的操作选项。点击数据源名称可以进入数据源详情页，查看该数据源的完整信息，包括数据表结构、统计数据、权限列表等。编辑功能允许用户修改数据源的名称和描述信息。导出功能可以将数据源中的数据导出为 Excel 格式，便于离线分析或与其他系统共享。

删除数据源是敏感操作，需要二次确认。删除数据源将同时删除该数据源下的所有数据表和数据记录，且无法恢复。在执行删除操作前，系统会显示将被删除的数据量和关联信息，要求用户明确确认。对于需要保留但不再使用的数据源，可以选择「归档」操作，归档后的数据源仍存在于系统中但不会显示在默认列表中。

## 六、数据表查看

### 6.1 访问数据表

拥有查询权限的用户可以查看数据源中的数据表。进入数据源详情页后，在「数据表」选项卡中列出了该数据源下的所有数据表。点击数据表名称即可进入数据表查看页面，该页面以表格形式展示数据内容。

数据表查看页面采用了 DataTables 插件，提供了强大的交互功能。表格顶部提供了搜索框，可以对所有列进行全文搜索；每列标题处提供了筛选器，可以选择特定值进行过滤。分页功能将数据分批显示，默认每页显示 25 条记录，可以在设置中调整为 10、25、50、100 条或全部显示。排序功能允许按任意列进行升序或降序排列，支持多列联合排序。

页面还显示了数据表的元信息，包括总记录数、创建时间、最后更新时间等。如果用户同时拥有查看表头权限，页面上方会显示字段结构信息，包括字段名称、数据类型、是否可空等详细信息。这些信息对于理解数据结构和编写查询条件非常有帮助。

### 6.2 高级查询功能

除了简单的浏览和搜索，数据表查看页面还提供了高级查询功能，满足复杂的数据检索需求。点击「高级查询」按钮，将展开查询构建器界面。查询构建器采用可视化的方式，用户可以通过下拉菜单和输入框组合查询条件，无需编写 SQL 语句。

查询条件支持多种逻辑组合：AND（与）关系要求所有条件同时满足；OR（或）关系满足任一条件即可。条件类型包括等于、不等于、大于、小于、包含、不包含、开头是、结尾是等。对于日期类型字段，还支持日期范围查询。构建完查询条件后，点击「执行查询」按钮即可得到筛选结果，结果可以导出为 Excel 文件。

历史查询功能保存了用户最近执行的查询记录，方便重复执行相同的查询。系统还支持查询结果的收藏和共享，用户可以将常用查询保存为「我的查询」，也可以生成分享链接发送给其他用户。管理员可以查看系统中的公共查询模板，促进知识共享和最佳实践传播。

### 6.3 数据导出

数据导出功能允许用户将查询结果或完整数据表导出为 Excel 格式。在数据表查看页面，点击「导出」按钮，弹出导出设置对话框。用户可以选择导出全部数据或仅导出当前查询结果，选择是否包含字段标题行，设置导出文件的命名等选项。

对于大型数据表，系统支持分批导出以避免内存问题。如果数据量超过导出限制，系统会提示用户缩小导出范围或使用命令行工具进行批量导出。导出文件采用 UTF-8 编码，确保中文字符正确显示。文件格式兼容 Excel 2010 及以后版本，可以在 Excel、WPS 表格或其他电子表格软件中直接打开。

定时导出功能适用于需要定期生成报表的场景。用户可以设置导出任务的执行频率（每天、每周、每月）、执行时间、输出目录等参数。系统会在后台自动执行导出任务，并将生成的文件保存到指定位置或通过邮件发送。定时任务信息在「我的任务」页面进行管理，可以随时启用、禁用或修改任务配置。

## 七、权限管理

### 7.1 权限类型说明

系统实现了精细的权限控制机制，定义了多个权限维度以满足不同场景的访问控制需求。查看表头权限（view_header）允许用户查看数据表的字段定义和结构信息，这对于理解数据内容和编写查询条件是必需的。拥有此权限的用户可以看到字段名称、数据类型、注释说明等元数据，但不包含实际的数据记录。

查询权限（query_data）允许用户检索和浏览数据表中的实际记录。拥有此权限的用户可以执行数据筛选、排序、导出等操作，但无法修改数据源的结构或添加新数据。导入权限（import_data）允许用户向数据源中导入新的 Excel 数据，适用于需要批量添加记录的场景。拥有此权限的用户通常同时拥有查询权限，以便验证导入的数据。

编辑权限（edit_schema）允许用户修改数据表的字段定义、调整字段顺序、添加或删除字段等结构变更操作。此权限应谨慎授予，因为不正确的结构变更可能导致数据丢失或损坏。管理权限（admin）包含以上所有权限，并额外授予权限分配和回收的权限。拥有管理权限的用户可以决定其他用户对该数据源的访问权限。

### 7.2 权限分配操作

权限分配通过权限管理界面进行操作。进入数据源详情页，切换到「权限管理」选项卡，即可看到当前所有用户的权限列表。添加新权限时，点击「添加权限」按钮，弹出权限分配表单。在表单中选择目标用户、权限类型、有效期，确认后即可完成分配。

权限有效期是权限管理的重要特性。默认情况下，权限授予后永久有效，但管理员可以设置具体的过期日期。这对于临时项目协作、外部分享等场景特别有用。系统会在权限即将过期时发送提醒通知，也会在权限过期后自动回收，用户将立即失去对该数据源的访问权限。过期权限可以在权限历史中查看，便于审计追溯。

批量操作功能提高了权限管理效率。管理员可以同时选中多个用户进行批量授权或批量回收。批量操作界面清晰展示了将要变更的权限详情，避免误操作。对于需要为整个用户组统一配置权限的场景，系统支持基于角色的权限预设，可以预先定义包含多种权限的「权限模板」，应用时只需选择模板即可完成配置。

### 7.3 权限继承与组合

当用户对某个数据源拥有多个不同维度的权限时，系统采用权限累加原则生效。权限效果可以组合，例如同时拥有查询权限和导入权限的用户，既可以查看现有数据，也可以添加新数据。需要注意的是，权限组合不会产生额外的限制，始终以最宽泛的权限生效。

权限继承机制简化了跨数据源的权限管理。如果用户被授予某个「数据源组」的权限，该组内所有数据源都将继承相同的权限设置。这在组织拥有多个相关数据源时特别有用，可以避免重复配置。数据源组的创建和管理在系统管理模块中进行，管理员可以将逻辑相关的数据源归入同一组。

权限冲突处理遵循显式优先原则。如果用户通过不同途径获得了对同一数据源的不同权限，系统以明确授予的最高权限为准，不会产生权限限制效果。权限回收采用严格模式，一旦权限被回收，该用户对该数据源的所有访问都将被禁止，包括通过其他途径可能获得的权限。

### 7.4 权限审计

系统记录所有权限变更操作，形成完整的审计日志。审计日志包括权限授予、权限回收、权限变更等操作，记录了操作时间、操作人、目标用户、目标数据源、变更前后的权限状态等详细信息。审计日志不可被删除或修改，确保了日志的真实性和可追溯性。

权限审计功能支持多维度的查询和统计。管理员可以按时间范围查询特定用户的权限历史，也可以按数据源查看所有权限分配记录。统计报表提供了权限分布概览，包括各数据源的权限数量、各权限类型的分布、活跃用户比例等指标。这些数据有助于管理员了解权限使用情况，发现潜在的权限过度分配问题。

权限合规检查功能可以定期扫描系统中的权限配置，识别潜在的安全风险。检查项包括：超过90天未使用的用户权限、超期未处理的权限请求、过于宽泛的权限组合等。检查结果以报告形式呈现，管理员可以根据报告进行权限优化，提升系统整体安全性。

## 八、API 接口

### 8.1 API 概述

系统提供了一套完整的 RESTful API 接口，支持程序化访问和系统集成。API 采用 JSON 格式进行数据交换，遵循标准的 HTTP 协议规范。所有 API 请求都需要用户认证，认证方式支持会话 Cookie 和 API Token 两种方式。

API Token 是专为程序访问设计的认证方式，相比会话 Cookie 更加灵活和安全。用户在设置页面可以生成 API Token，每个 Token 都有独立的名称和权限范围。生成的 Token 只显示一次，之后将无法再次查看，请妥善保存。Token 支持设置过期时间，过期后自动失效需要重新生成。

API 文档采用 OpenAPI（Swagger）规范编写，可以通过访问 `/api/docs` 路径查看交互式 API 文档。文档页面提供了接口说明、参数定义、请求示例、响应示例等完整信息，并支持在线测试 API 调用。对于需要集成到 CI/CD 流水线或第三方系统的场景，可以下载 OpenAPI 规范文件用于代码生成。

### 8.2 认证接口

用户登录 API 用于获取认证凭证。请求路径为 `POST /api/auth/login`，请求体需要包含 `username` 和 `password` 字段。登录成功后，响应中会包含用户信息和会话 Cookie。对于 API Token 方式认证，请求头需要携带 `Authorization: Bearer <token>` 格式的认证信息。

```json
// 登录请求示例
{
    "username": "admin",
    "password": "your_password"
}

// 登录响应示例
{
    "success": true,
    "user": {
        "id": 1,
        "username": "admin",
        "email": "admin@example.com",
        "user_type": "admin"
    },
    "token": "your_api_token_if_requested"
}
```

用户注册 API 用于创建新账户。请求路径为 `POST /api/auth/register`，请求体需要包含 `username`、`email`、`password` 等必填字段，以及可选的 `password_confirm` 字段进行密码确认。注册成功后返回用户信息和认证凭证。邮箱验证可能需要额外的步骤完成账户激活。

### 8.3 数据源接口

数据源列表 API 返回当前用户有权限访问的所有数据源。请求路径为 `GET /api/data-sources`，此接口支持分页和筛选参数。响应包含数据源总数、当前页数据、每页数量等分页信息，以及每个数据源的基本信息。

```json
// 响应示例
{
    "success": true,
    "data": [
        {
            "id": 1,
            "name": "金属材料性能数据",
            "description": "包含常用金属材料的力学性能测试数据",
            "table_count": 3,
            "record_count": 1250,
            "created_at": "2024-01-15T10:30:00Z",
            "updated_at": "2024-03-20T14:45:00Z"
        }
    ],
    "pagination": {
        "page": 1,
        "per_page": 20,
        "total": 5
    }
}
```

数据源详情 API 返回指定数据源的完整信息。请求路径为 `GET /api/data-sources/{id}`，响应包含数据源的所有属性、包含的数据表列表、权限列表等详细信息。创建数据源 API 为 `POST /api/data-sources`，请求体包含 `name`、`description` 等字段，以及可选的 `file` 字段用于上传初始数据文件。

### 8.4 数据表接口

数据表列表 API 返回指定数据源下的所有数据表。请求路径为 `GET /api/data-sources/{id}/tables`，响应包含每个数据表的名称、字段定义、记录数量等信息。数据表详情 API 为 `GET /api/data-sources/{id}/tables/{table_name}`，返回数据表的完整结构定义和示例数据。

数据查询 API 是最常用的接口之一，支持灵活的数据检索。请求路径为 `POST /api/data-sources/{id}/tables/{table_name}/query`，请求体采用 JSON 格式定义查询条件。

```json
// 查询请求示例
{
    "filters": [
        {"field": "material_type", "operator": "eq", "value": "铝合金"},
        {"field": "tensile_strength", "operator": "gte", "value": 400}
    ],
    "order_by": [{"field": "tensile_strength", "direction": "desc"}],
    "limit": 100,
    "offset": 0
}
```

查询响应返回符合条件的记录列表和总数统计。系统对查询结果进行了优化，支持分页查询以处理大型数据集。导出数据 API 为 `POST /api/data-sources/{id}/tables/{table_name}/export`，请求参数与查询接口类似，但返回的是 Excel 文件下载。

### 8.5 导入导出接口

数据导入 API 用于通过程序方式导入数据。请求路径为 `POST /api/data-sources/{id}/import`，请求采用 `multipart/form-data` 格式，包含 `file` 字段上传 Excel 文件，以及可选的 `options` 字段指定导入选项。导入是异步执行的，接口立即返回任务 ID，用户可以通过任务 ID 查询导入进度和结果。

```json
// 导入请求
POST /api/data-sources/1/import
Content-Type: multipart/form-data

file: [Excel文件]
options: {"skip_rows": 0, "has_header": true}
```

权限管理 API 提供了程序化的权限控制能力。查询权限列表为 `GET /api/data-sources/{id}/permissions`，添加权限为 `POST /api/data-sources/{id}/permissions`，请求体包含 `user_id` 和 `permissions` 数组。回收权限为 `DELETE /api/data-sources/{id}/permissions/{user_id}`。

## 九、系统管理

### 9.1 管理员仪表板

管理员仪表板提供了系统运行状态的全局视图。首页展示关键指标卡片，包括用户总数、数据源数量、数据表数量、今日访问量、系统负载等。趋势图表显示了这些指标随时间的变化曲线，帮助管理员把握系统发展趋势。异常告警区域显示需要关注的异常情况，如磁盘空间不足、错误日志激增、异常登录行为等。

系统健康检查功能可以快速诊断系统运行状况。点击「健康检查」按钮，系统将依次检查数据库连接、存储空间、服务进程、日志文件等关键组件的状态。检查结果以可视化方式呈现，异常项会高亮显示并提供修复建议。健康检查也可以配置为定期自动执行，发现问题及时通知管理员。

审计日志概览是管理员仪表板的重要组成部分。系统记录了所有重要操作的审计信息，包括用户登录、数据访问、权限变更、系统配置修改等。管理员可以快速浏览最近的审计事件，也可以进入详细日志页面进行深度查询和导出。审计日志保留期限可以在系统设置中配置，默认为保留 180 天。

### 9.2 用户管理功能

用户管理界面提供了完整的用户生命周期管理能力。用户列表采用分页展示，支持按用户名、邮箱、角色、注册时间、最后登录时间等条件进行筛选和搜索。批量操作功能支持批量启用、禁用、删除用户，以及批量分配角色。

创建用户功能允许管理员手动创建账户，适用于批量导入用户或为特殊人员创建账户的场景。创建时可以设置用户名、邮箱、角色、初始密码等信息。系统支持用户导入功能，可以从 CSV 文件批量创建用户，简化了企业环境的用户初始化工作。

用户详情页面包含了该用户的完整信息和使用统计。用户属性区域可以编辑用户的基本信息、角色分配、账户状态等。用户权限区域显示了用户拥有的所有数据源权限列表，可以在这里直接进行权限调整。用户活动区域记录了该用户的登录历史、重要操作记录，便于追踪用户行为和进行安全审计。

### 9.3 系统配置

系统配置页面允许管理员调整系统的各项运行参数。基础配置包括站点名称、Logo 图片、页脚信息等品牌设置，以及时区选择、语言设置、日期格式等本地化配置。这些配置影响整个系统的显示风格和用户界面体验。

安全配置是系统配置的重点区域。包括密码策略配置：密码最小长度、复杂度要求、密码历史限制、登录失败锁定策略等。会话配置：会话超时时间、同时登录设备数限制、Cookie 安全策略等。API 配置：API Token 有效期、API 访问频率限制、IP 白名单等。

数据库配置显示当前的数据库连接信息和存储统计。管理员可以查看数据库文件大小、表数量、索引大小等详细信息。日志配置允许调整日志级别、日志文件路径、日志保留策略等。邮件配置用于设置系统通知邮件的 SMTP 服务器信息，支持配置多个邮件模板以满足不同的通知需求。

### 9.4 数据维护

数据备份功能确保数据安全。系统支持手动备份和定时备份两种方式。手动备份可以立即生成数据库快照，下载到本地保存。定时备份可以设置备份频率（每天、每周、每月）和保留数量，系统将自动执行备份任务并清理过期备份。备份文件采用加密压缩格式，确保数据在存储和传输过程中的安全性。

数据恢复功能可以将系统恢复到指定的备份点。进入「数据维护」页面，选择要恢复的备份文件，确认恢复操作。恢复过程会替换当前数据库，请谨慎操作。建议在恢复前先创建一次备份，以便需要时可以回滚。系统也支持部分恢复，可以选择只恢复特定数据源的数据。

数据清理功能帮助管理员维护系统性能。过期数据清理可以删除超过指定期限的数据记录，如旧的审计日志、导入任务记录、会话数据等。孤立数据清理可以发现和删除不再关联到任何数据源的孤立记录。优化功能可以重建数据库索引、整理存储空间，提升查询性能。

## 十、故障排除

### 10.1 常见问题解答

**问题：登录时提示「用户名或密码错误」但确认输入正确**

这通常是由于密码输入法的全半角切换问题或特殊字符输入错误导致的。建议先尝试使用虚拟键盘重新输入密码，确认大小写和符号是否正确。如果问题持续，可能是账户已被锁定，可以等待 15 分钟后重试或联系管理员检查账户状态。

**问题：数据导入失败，提示「文件格式不支持」**

请确认上传的文件是标准的 Excel 格式（.xlsx 或 .xls），而非 CSV 或其他格式。某些 Excel 文件可能存在格式损坏或使用了非标准扩展名，建议用 Excel 重新打开并另存为标准格式后再上传。同时检查文件大小是否超过 50MB 限制。

**问题：查询数据时页面加载缓慢或超时**

这通常发生在数据表包含大量记录的情况下。建议优化查询条件以缩小结果范围，或使用分页功能分批加载数据。如果某个数据表长期访问缓慢，可能需要考虑数据归档或分表策略。管理员可以在系统监控中查看查询性能统计，识别慢查询并进行优化。

**问题：API 请求返回 403 权限被拒绝**

首先确认请求中是否包含有效的认证信息（会话 Cookie 或 API Token）。然后检查 Token 的权限范围是否包含请求的资源。用户可能对目标数据源没有相应权限，或者 Token 已过期失效。可以尝试使用管理员账户的 Token 确认接口本身是否正常工作。

### 10.2 日志查看

系统日志是故障排查的重要信息来源。应用日志文件位于 `material_database/logs/app.log`，记录了 Web 请求处理、数据库操作、错误异常等信息。日志采用分级记录方式，按日期分割文件便于管理和检索。

查看最近的错误日志可以使用以下命令：

```bash
tail -n 100 logs/app.log | grep ERROR
```

这将显示最近的 100 行日志中包含「ERROR」关键字的条目。对于性能问题，可以查找「WARNING」级别的日志了解潜在瓶颈。对于认证问题，可以查找包含「login」或「auth」关键字的日志条目。

如果需要更详细的调试信息，可以在系统配置中将日志级别调整为「DEBUG」。但请注意，DEBUG 级别会生成大量日志，影响系统性能和日志文件大小，只建议在排查问题时临时启用。

### 10.3 联系支持

如果在阅读本手册后仍有无法解决的问题，请通过以下方式获取技术支持。首先建议搜索系统的在线知识库，那里可能有其他用户遇到过的类似问题及其解决方案。如果问题紧急或涉及安全漏洞，请直接联系系统管理员。

在提交问题时，请提供以下信息以加速问题处理：问题发生的准确时间、复现问题的操作步骤、相关的截图或错误信息、您的浏览器版本和操作系统版本、您的用户名和遇到问题的数据源名称。完整的问题描述将帮助技术支持团队快速定位和解决问题。

### 附录三：Excel 导入规范

导入的 Excel 文件应满足以下要求。文件格式必须为 .xlsx 或 .xls，不支持 CSV 或其他格式。文件大小限制为 50MB。首行必须包含列标题，作为数据表的字段名称。数据区域从第二行开始，每行表示一条记录。空行将被自动跳过。日期格式应使用 Excel 识别的标准日期格式，如「2024-03-20」或「2024/03/20」。数字列应避免包含文本内容，否则可能导致类型识别错误。

对于包含复杂格式的 Excel 文件（如合并单元格、条件格式等），建议在导入前清理格式，只保留纯数据和标题。宏和公式会被忽略，导入后将不保留任何计算逻辑。
